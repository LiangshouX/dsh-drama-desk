# 多角度资产（turnaround / 三视图 / 九宫格）—— 研究结论与本项目落地方案

> 2026-11-11 调研产出。目的：评估「用三视图甚至九视图锁定人物一致性」这条行业经验，
> 对本作品是否成立、该怎么用。
> 结论先行：**思路对，形式要改。板是模具，不是弹药。**

---

## 一、一句话结论

三视图/九视图的价值在**「生成参考图」这一环**（把设定钉死、给返工当对照基准），
不在**「喂给视频模型」这一环**。
把整板直接当视频参考图，实测反例明确：模型可能试图在一个镜头里画出多个角度。

**行业主流工作流：生成板 → 裁出最佳单格 → 把单格当锚。**

---

## 二、有效性评估（按证据强度）

| 判断 | 强度 |
|---|---|
| 作为生图侧的设定锚：极有用。由定妆脸派生正/3-4/侧/背，能一次钉死「服装花纹、发型后脑、背部结构」——纯文字写 `front view, side view, back view` 几乎必然出三个不同的人 | 强 |
| 作为存档与返工基准：有用。它是验收单，不是生成输入——对着板子看这张脸对不对，有偏差就回板子改 | 强 |
| 「九视图」本身不是行业标准。标准件是 **turnaround（4 角度）** 与 **expression sheet（同角度多表情）** 两份不同产物；3×3 九宫格本质是「参考图生成的产物集」，不是单一的一致性装置 | 强 |
| 整板直接当视频参考图：**有害**。从业者明确「有些视频模型在被喂 turnaround 板时，会试图在一个镜头里画出多个角度」；应给「一张干净头像 + 一张全身」 | 中（但方向精准） |
| 参考图并非越多越好：一张互相冲突的参考比少图更糟；单镜建议控制在 4 张以内 | 中 |
| 「三视图各格不统一」是最常见失败模式：正视图稳、侧视图中、背视图低。**不合格的板不如不用** | 中 |

### 关键写作约束（做板时必须写死）

- 框架词逐字复用、只换视角词：白底 / 全身 / 站立 / 同一套服装描述每一格都重复
- 每个角度**重述一次识别性特征**（发色、腰带、袖口长度），否则模型在背面悄悄丢掉
- `proportions locked identical across every angle`
- **不要锁姿势**（否则四格是同一张图旋转四次）
- **手里不要拿道具**（道具跨角度必然不一致）
- 正/侧/背统一光影，否则模型「分不清哪个是真特征」
- 背视图会自己发明配件 → 背视图只要求服装大形对得上即算合格

## 三、MiniMax-H3 专项（对本项目最相关）

### H3 视频多图参考的官方用法

- 上限：图片 ≤9、视频 ≤3、音频 ≤3、混合总计 ≤12 文件
- 角色标注只有 5 个值：`first_frame` / `last_frame` / `reference_image` /
  `reference_video` / `reference_audio`
- **没有「Picture N」这种编号 role**——图序由 content 数组顺序决定，提示词里用自然语言「图1/图2」指代
- 官方提示词范式就是分工声明式，与我们的三锚架构同构：
  `图2作为固定人物参考，保持黑色半扎长发、银色镂空发冠……一致。图1作为镜头分镜与节奏参考。`
- ⚠ **i2v（首帧）与 r2v（多参考）互斥**：content 里出现 `reference_image` 就不能再出现 `first_frame`

### H3-Image 生成设定板

- 参考图 1–16 张，**上传顺序 = Picture 编号**；提示词 ≤32000 字符；不支持 mask；不幂等
- 「多格面板（one image with several consistent panels）」在官方文档里**未见明文能力声明** → 需探针实测
- 已实测可行的做法：**一次出一张横版 16:9 的四视图板**（正/3-4/侧/背），比 3×3 九宫格更稳
  （三视图的失败主要在背视图，3×3 会放大失败面）

## 四、给本作品的落地方案

### 改哪一层

**不替换现有身份锚。** 定妆脸仍是唯一身份真源
（AGENTS.md 与配方 §1 的「每张图只承担一个职责」不动）。
新增**第四类资产：多角度资产包**，定位为「视频生成的补充参考」与「返工时的对照基准」，
不进入日常生图链路。

### 4 个角色各做什么

| 角色 | 做什么 | 优先级 | 理由 |
|---|---|---|---|
| 主角 | 4 视图板（正/3-4/侧/背）+ 面部特写；裁出正面、3/4 侧入 H3 参考 | **P0** | 出场密度最高；年龄感漂移代价最大 |
| 店主 | 4 视图板 + 面部特写 | **P1** | 60 岁年龄漂移风险最高；结构性对手，一眼要认得出 |
| 哥哥 | 3 视图（正/3-4/侧，跳过背面） | P2 | 年轻角色漂移较小 |
| 小贩 | 暂不做 | P3 | 配角、镜头少 |
| 关键道具 | 各出一张三视图（换正/侧/背） | P2 | 配合 R4；道具板比人物板便宜且更稳 |

### H3 提交写法

走 **r2v（多模态参考）**，因为要三视图必然放弃首帧锁定。
content 顺序：`text` → `reference_image`（角色正面裁切图）→ `reference_image`（角色 3/4 侧裁切图）
→ `reference_image`（场景锚）→（必要时）`reference_video`。

提示词首句沿用官方范式：
`图1是主角的正面身份参考，图2是主角的四分之三侧面参考，图3是场景参考。人物五官、脸型、发型、服装、配饰、身材比例全程不变，保持三张参考图统一光影与质感。`

### 成本

按 2K 标准价（文生 ¥0.153 / 编辑 1 图 ¥0.1747 / 编辑 3 图 ¥0.2746）：

- 主角 4 视图板：1 次编辑 ≈ ¥0.27，按出图率 1/3 重抽 2–3 次 → ≈ ¥0.8
- 店主同量 ≈ ¥0.8；哥哥 3 视图 ≈ ¥0.6；4 道具 ≈ ¥0.6
- **资产层一次性总计 ≈ ¥2.8–3.5**

对比：H3 视频 768P ¥0.50/秒，一个 5 秒镜头 ¥2.5 —— 资产层成本不足两个镜头。

### 已知风险与回退

1. **背视图不可靠** → 回退：不做背面，改「正 + 3/4 + 侧」；或背面只要求服装大形对得上
2. **整板当锚会拖累单图** → 回退：永远裁单格；若裁切后仍不稳，说明板子质量不达标，
   回退到「单张定妆脸 + 补充描述词」（只补缺失细节，不重写角色描述）
3. **H3 i2v/r2v 互斥** → 回退：某镜头首帧必须精确时改走 i2v + 单张正面参考，牺牲多角度信息
4. **参考图过多/互相冲突** → 回退：单镜参考图 ≤4 张（角色 2 + 场景 1 + 道具 1）
5. **H3-Image 九宫格能力未核实** → 回退：改走「逐张生成 + 参考图复用 + 事后拼板」

### 建议的最小验证实验（半天，约 ¥3）

主角出 1 张 4 视图板 → 人眼验收 → 裁出正面/3-4 侧 → 用**同一提示词**跑 3 条 5 秒镜头：

- A 组：仅定妆脸
- B 组：定妆脸 + 整板
- C 组：定妆脸 + 裁切两图

逐组对比脸部锐度、转身时轮廓、服装花纹是否漂移。
C 明显优于 A、B → 按上表推进；三组无差异 → 本课题对本作判定为低优先级，
板子只留作验收基准。

## 五、与本片现状的关系（2026-11-11 核对）

- 本片角色一致性靠**三锚架构**（身份锚 / 风格锚 / 场景锚）已经成立，20 张参考图用户已评「及格线」
- `shots.json` 单镜参考图已控制在 ≤4 张，R2/R4/R7 已在生成脚本里做机器校验
- **多角度板目前是"没有的资产"，不是"已证明无效"**——建议先做上面那个 A/B/C 最小实验再决定投不投
