# 探针方法论与验收

> 生图是**随机采样**过程。想得出可写进规则的结论，必须按实验方法做，否则会把噪声当因果。

---

## 1. 单张对比为什么不可信（规则 A6）

同一段提示词、同一张锚，跑两次，输出可以差出：
- 构图（人物偏左 / 偏右 / 居中）
- 光比（平亮 / 强对比）
- 脸的幼态程度
- 服装细节（开衩位置、饰品有无）

**实测**：仅改排除项的 3 张（0 条 / 2 条 / 7 条）之间，差异大到超过"题材不同"带来的差异。**在 n=1 上做 A/B，结论是随机的。**

**纪律**：
- 任何对比至少 **n=2**（理想 n=3），且**除被测变量外其他一切逐字相同**。
- 用**读数比对**代替看图（见 §3）：跑 `image_qc.py` 出体检表，看数字与组内极差。
  原「拼图横向比」已废弃——拼图会卡死会话，且模型打分带噪声。
- 结论先写成"假设"，攒够证据再升级为规则。

## 2. 探针矩阵设计

一次提交一个矩阵（≤10 条 request），每条只改一个变量。

```
基线            BASE：最佳锚 + 机制型词表 + 中近景 + 少量排除
变量组 A 锚质量  同一 prompt，换 3–4 张不同档次的锚
变量组 B 词表    同一锚同一主体，换 4 种语汇簇
变量组 C 景别    同一锚同一主体，特写 / 中近景 / 全身
变量组 D 排除项  同一 prompt，0 条 / 2 条 / 7 条
变量组 E 题材    同一锚同一词表，换 4 个场景
```

**成本控制**：2K 单张编辑（1 参考图）约 ¥0.175。一次 7 条 ≈ ¥1.2。探针阶段一律 2K，不上 4K。

## 3. 读数比对（取代拼图比对）

> ⚠️ **2026-11-15 重大变更**：原 §3「拼图比对脚本」已废弃。
> 拼图会被模型输入审核判为敏感并**永久卡死会话**（详见 §3.0）。
> 现在改为**读数比对**：模型只读文本报告，不读任何图。

### 3.0 为什么不能再拼图（事故记录）

MiniMax 输入过滤会把「多张人脸 + 大像素量」的拼贴图判为 `new_sensitive`：

```
input new_sensitive, messages[596]'s content[2] image is sensitive (1026)
```

后果是**会话永久卡死**：每轮请求重放历史 → 图还在 → 每轮被拒 → 重试 5 次
→ step 失败 → 你再发消息，还是同一份 payload，还是被拒。**重试无用。**

本项目已因此卡死过 3 个会话，每次损失数天进度，需要外部工具手术解封。

实测判据（**不是"有人脸就危险"**）：

| 图 | 结果 |
|---|---|
| 单张 2048×2048 / 4096×4096 人脸 | **通过** |
| 拼图 1800×1152（12 格人脸） | **3/3 被拒** |
| 同一张缩到 1200 / 1024 / 900 / 768px | 全部通过 |
| 拼图 1270×946（2 列） | 通过 |
| 切成单行 / 单格 | 通过 |

**结论：判据是「多张人脸 + 大像素量」的组合。单图安全，大幅拼图危险。**

### 3.1 用 `image_qc.py` 出体检表

```bash
# 一组探针跑完，直接出体检表（不产生任何图片）
python tools/image_qc.py --dir <探针目录> --glob "*.jpg"

# 单张
python tools/image_qc.py --image foo.jpg

# 出 JSON 给下游脚本吃
python tools/image_qc.py --dir ... --json --out _qc.json
```

输出示例：

```

文件                            饱和     S10%   明度     明度σ    冷暖     对比     边缘     色丰
--------------------------------------------------------------------------------------------
P1b_aling_face_01.jpg         0.3536 0.1048 139.66 61.93  39.67  54.68  0.0741 0.185
P1s_shopkeeper_face_02.jpg    0.2393 0.0952 154.57 62.1   34.98  55.64  0.1309 0.1572

      - 饱和不足 0.239<0.28（画风偏灰/白纸感）
```

**模型直接读这段文本就够了，不需要看图。**

### 3.2 阈值从哪来（不要凭感觉调）

阈值是**用对照组实测校准**的，校准集在仓库里可复现：

| 组 | 来源 | sat | 明度 | 色丰 |
|---|---|---|---|---|
| **好图** | `.tmp/.example/*/MiniMax-H3-Image.png`（3 张） | **0.344–0.365** | 119–170 | 0.157–0.218 |
| **v1 坏图** | `.depracated/v1-*/refs/*_work_full_cn.jpg` | **0.050–0.101** | **201–224** | 0.051–0.079 |

| 指标 | 判废阈值 | 依据 |
|---|---|---|
| `sat_mean` | **≥ 0.28** | 项目宪法硬门槛；好图 ≥0.344，坏图 ≤0.101 |
| `value_mean` | **≤ 195** | 好图 ≤170，坏图 ≥201（接近白纸） |
| `sat_p10` | **≥ 0.05** | 好图 ≥0.089，坏图 ≤0.032（大片死灰） |
| `colorfulness` | **≥ 0.12** | 好图 ≥0.157，坏图 ≤0.079 |

**⚠️ 以下三项实测无区分度，只作参考，不得用于判废**：

- `value_std`（明度σ）：好 55–59 / 坏 61–86
- `contrast`（RMS）：好 51–60 / 坏 63–86
- `edge_density`：好 0.068–0.134 / 坏 0.049–0.065

后两个**坏图反而更高**——设定表有硬阴影边界和清晰轮廓线。
「对比度高 = 好」、「边缘多 = 好」是错的直觉。

### 3.3 组内方差仍然必须看（规则 A6 不变）

`image_qc.py` 会自动算同组极差：

```
组内一致性
组                 n   饱和均值      饱和极差      判定
P2a_s             2   0.2622    0.0764
```

**极差 > 0.10 时，单张结论不可信**——必须加大 n 或换判据。
这条规则没有变，只是"拼图看"换成了"看极差数字"。

### 3.4 什么时候**才**需要人眼看图

读数覆盖不了审美的最后一段。以下情况请**人**亲自看原图（不是拼图）：

- 面部细节（眼褶、高光点、虹膜纹理、年龄感）
- 手的结构（多指、糊成一团）
- 文字错误（道具上的汉字）
- 空间关系（家具位移、时代穿帮）
- 「这个味道对不对」——最终审美判断

**人看原图时不需要拼图**：直接开原文件，肉眼一张张翻。拼图的唯一好处是
"横向比对省事"，但它换来的代价是会话永久卡死——**不划算**。

如果确实要拼（只给自己看），拼完**不要 `read_image`**，只在你自己的看图软件里打开。

### 3.5 评分维度（§4 的替代）

原 §4 让模型打 5 个 1–5 分（骨相/光比/材质/纵深/语汇）——**这个做法已废弃**，
因为模型看图既有卡死风险，打分也带噪声。

现在分两层：

| 层 | 谁判 | 怎么判 |
|---|---|---|
| **可量化层** | 脚本 | `image_qc.py` 的 4 项判废 + 组内极差 |
| **审美层** | **人** | 人眼过原图，用下面的清单 |

审美层清单保留给**人**用（不是给模型）：

| 维度 | 看什么 |
|---|---|
| 骨相 | 脸有没有结构（颧骨、下颌、年龄感），还是模板娃娃脸 |
| 材质 | 织物/皮肤/金属是否有密度，还是塑料感 |
| 纵深 | 前景/中景/背景三层是否成立 |
| 语汇 | 是否落在预期的那一簇（不是靠"好看"判断） |

### 3.6 量化指标测不出「精致度」——盲区实测记录（2026-11-15）

用户于 2026-11-15 定了过关线：**人物画面至少要达到
`docs/对照样例/2026-11-15-三组跨模型对照/二次元立绘/MiniMax-H3-Image.jpg` 的水平。**

把达标图与探针产出用同一套指标量：

| 图 | 饱和 | 主体明度 | 背景明度 | 明度差 | 视觉判断 |
|---|---|---|---|---|---|
| 达标图（二次元立绘） | 0.334 | 157.4 | 130.5 | **+26.9** | 过关 |
| 探针 P1v（店主） | 0.330 | 156.1 | 126.2 | **+29.9** | **不过关** |
| 探针 P1b（主角） | 0.354 | 122.7 | 117.4 | +5.3 | 不过关 |
| 探针 P1x（主角） | 0.362 | 149.7 | 102.1 | +47.6 | 过关 |

**结论**：
- 饱和度、明度差等指标**与"精致度"没有相关性**。P1v 的明度差比达标图还大，饱和度也达标，
  视觉上仍明显不如——差距全在**线条精细度与面部精度**上，这两样指标完全测不到。
- 也因此，**"主体/背景明度差"不能单独用作判废项**：达标图本身只有 +9.6 ~ +26.9，
  超出这个区间不代表更好。
- **指标只负责判"平不平"（灰不灰、有没有光），不负责判"精不精"。**
  后者必须由**人**过原图，或由**提示词条款**直接控制（见配方 §2 的「勾线极细」与 §3 面部精度条款）。

> 代价最低的提升路径（实测）：**只加一句「勾线极细，接近一根铅笔线的粗细，线条末端收成尖」**，
> 脸就从"欧美写实卡通脸"变成"二次元美型脸"，组内极差从 0.041 降到 0.004。
> **线条粗细是精致度的总开关**，而它此前从未被写进任何提示词。

## 5. 验收清单（人工过）

**通用**
- [ ] 与锚并排：光比、骨相、材质是否同档
- [ ] 脸占画面是否 ≥1/4
- [ ] 暗部是否有层次
- [ ] 背景是否三层纵深
- [ ] 有无文字/水印/第二人物
- [ ] 手：多指/糊成一团？
- [ ] 与上一张并排：画风是否漂？

**人物**
- [ ] 眼睛：上眼睑褶？两点高光？虹膜纹理？瞳孔是圆的？
- [ ] 皮肤：有无微纹理，还是均匀瓷皮？
- [ ] 年龄：说二十五岁的像二十五岁吗？
- [ ] 姿态：手在做什么，写清了吗？

**场景**
- [ ] 空间关系是否与场景锚一致、家具有没有位移
- [ ] 时代感穿帮（旧物/现代物件）
- [ ] 出现的汉字对不对

---

## 6. 什么时候跑探针

- 新题材 / 新画风第一次做 → 必跑（3–4 张对照）
- 要下结论"某个写法更好" → 必跑
- 只是要一张图 → 不跑，直接按模板出
- 批量量产前 → 跑一组"锚质量 + 语汇"对照，把最佳参数固化成模板

---

## 7. 失败处理

- **接口不幂等**：重复提交＝重复扣费。超时先查台账与 provider 任务列表，**不要直接重发**。
- **单张参考图读取失败 → 整条 request 失败**（不是跳过该图）。批量前先验证 URL 可达；临时 URL 1 小时过期，批量前一次性全部上传。
- 连续 2 次修正后仍失败 → 停下来报告原因，不要换参数乱试。
