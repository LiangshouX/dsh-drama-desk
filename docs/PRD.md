# 导演工作台 · 产品说明书

> **唯一现行产品说明书。** 本文档只描述**已经有的功能**——
> 需要一份「打算怎么做」的规划稿时，去工作区根部的 `PRD.md`（历史稿，已归档）；
> 两处不一致时，以本文为准。
>
> **一句话**：把 AI 短剧生产线里那些只存在于代码、JSON 和 agent 脑子里的规范，
> 变成一个**人能读、能改、能做取舍的导演台**。
>
> 这份文档只描述**已经有的功能**。单独拿出来读也应该能看懂——
> 不需要任何仓库外的上下文。

---

## 1. 这是什么

一个跑在 DeepSeek Harness（下称 DSH）里的**插件**，在 DSH 左侧栏有一个自己的入口
（和别的插件同级），标题是「导演工作台」。

它管一部 AI 短剧从想法到成片的**九个阶段**，每个阶段有自己的产物、判定线和可改的字段。
导演坐在这块屏幕前能看见：

- 这部片子**现在到哪一步了**，下一阶段还差什么；
- 每一镜的**状态**（出了没有、过没过体检、卡在哪）；
- 每一镜的**依据**（为什么是这个状态、违反了哪条规则）；
- 每一镜的**内容**（提示词、参考图、成片、剧本节拍）；
- 并且能**直接改**，改完立刻知道后果。

### 1.1 不是什么

| 不是 | 为什么 |
|---|---|
| 出图 / 出视频的工具 | 生成由 **agent** 走「幂等三步」提交，插件**不发起付费生成** |
| 生成器的 UI 包装 | 插件的价值在生成**之前与之后**那段：判断、留痕、返工 |
| 项目管理看板 | 不是进度条和百分比，是让人**能做决定** |
| 一个只读查看器 | 每个阶段的核心字段都能改，改完立刻重跑体检 |

### 1.2 差异化的立足点

同类工具在**生成**上竞争，这个工作台在**判断**上竞争。

生成能力是模型提供的、一年一换；而「这一镜为什么不行」「我该改哪一处」
「改完会怎样」——这套方法论是复利的。工作台就是它的可交互载体。

## 2. 使用者与一条核心约束

| 角色 | 在意什么 | 在这里做什么 |
|---|---|---|
| **导演（人）** | 这一镜能不能过？问题在哪？我改了 X，会怎样 | 扫网格 → 点开一镜 → 读判定 → 改 → 看影响 → 决定重出 |
| **agent** | 现在该做什么？哪些镜有问题？规范是什么 | 读同一份数据、走同一套判定 |

> **核心约束：人和 agent 对「合不合格」的判断必须一致。**
>
> 做法是「**一个操作，两个调用者**」：每个操作在 Host 侧只实现一次，
> 界面按钮与 agent 工具调用**同一个方法**。禁止在两条路径里各写一遍。

## 3. 作品与目录

### 3.1 一个工作台只有一个总根

```
<「视频」目录>/DSH-DRAMA-DESK/          ← 唯一的总根（第一次使用时自动创建）
└── workspaces/
    ├── <work-id>/                      一部短剧 = 一个自包含目录
    └── <work-id>/
```

- 总根默认落在操作系统的**「视频」已知文件夹**下（Windows 会跟随用户的「位置」重定向，
  所以搬过盘也跟得住），通常不在系统盘——避免在不知不觉中撑爆 C 盘。
- **不要一部短剧开一个 DSH 工作区。** 所有作品共用一个 DSH 工作区，
  否则侧栏会碎成一堆，用户说不清哪份是最新的。
- 路径可以在设置里改，也可以留空走自动解析；界面永远写明**当前解析到哪、为什么是它**。

### 3.2 一部作品里有什么

```
workspaces/<work-id>/
├── work.json         作品元信息（标题、创建时间）
├── state.json        当前阶段、进度、预算、构思会话 id
├── scenes.json       场次表（含每场的 beats：动作行 / 台词 / 语气）
├── characters.json   角色卡与道具卡
├── shots.json        分镜表（每镜的机位、时长、画幅、光参数、参考图绑定）
├── assets.json       资产索引（只增不删，作废的标 deprecated）
├── ledger.json       生成台账（每次提交与花费）
├── creative/brief.md 创意简报（conceive 阶段的唯一出口）
├── refs/             参考图
├── prompts/slim/     提示词产物（可重编译、可丢弃）
├── prompts/overrides/ 人工改写的提示词（重编译会保留）
├── videos/           生成的视频片段
├── keyframes/        关键帧
└── verify/           验收报告（每镜一份）
```

**资产的唯一入口是 `assets.json`**：任何文件被使用之前都要登记；
作废不改删，只标 `status: deprecated` 并保留路径指向归档。

### 3.3 真源 / 派生 / 产物

界面上每个字段都属于三类之一，直接决定它能不能改：

| 类别 | 例子 | 能不能改 |
|---|---|---|
| **真源** | beats、镜头字段、角色卡、brief | ✅ 能改，改了就是新的真源 |
| **派生** | `shots.json` 里的 `description_en`、`dialogue` | ❌ 只读——由编译从 beats 生成，手改会被覆盖 |
| **产物** | `prompts/slim/*.prompt.txt` | ✅ 能改（存成人工覆盖），也能一键重编译 |

## 4. 九个阶段

阶段顺序是固定的，每个阶段有一个**唯一的结构化出口**，下游读上游产物而不是靠回忆。

| # | 阶段 | 出口产物 | 进入它的前置条件 | 界面能改什么 |
|---|---|---|---|---|
| 1 | `conceive` 创意 | `creative/brief.md` | — | 简报正文 |
| 2 | `outline` 大纲 | `scenes.json` 的场次骨架 | 简报非空 | 场次标题 / 功能 / 时长 / 摘要 / turn / 在场角色 |
| 3 | `characters` 角色 | `characters.json` + 参考图 | 至少一个场次 | 外貌 / 行为 / 音色 / 语气 / 状态 / 道具 / 参考图提示词 |
| 4 | `script` 剧本 | `scenes.json` 的 `beats[]` | 至少一张带 `role` 的角色参考图 | 增 / 删 / 改 / 移每一拍 |
| 5 | `storyboard` 分镜 | `shots.json` | 每个场次都有 beats | 机位 / 画幅 / 分辨率 / 时长 / 光参数 |
| 6 | `generate` 生成 | 视频资产 + 提示词资产 + 台账 | 每个镜头都有 `duration` 与 `camera` | 镜头字段 / 批注 / 提示词 |
| 7 | `verify` 验收 | `verify/<shot>.report.json` | 每个镜头都有已登记的视频资产 | 人工判定 / 复核人 / 问题清单 |
| 8 | `assemble` 装配 | 版本清单与缺口 | 每个镜头的 `status` 已是 `verified` | （读） |
| 9 | `deliver` 交付 | 成片 | 已登记成片 | （读） |

### 4.1 阶段推进的语义

> **点阶段节点 = 切视图，不是改状态。**

- 点任意阶段节点**立刻**切到那个阶段的视图，**没有确认框，也没有第二次点击**；
- 切过去是**预览态**：阶段条上正在预览的那一枚是虚线描边，
  已提交的进度仍是实心，并有一条横幅写着「已提交进度仍停在 X」；
- **只有你在这一阶段里改了东西**，总体进度才推进到这一阶段。

**保存与推进是分离的**：内容永远先保存；前置条件不满足只是进度不动，
缺口如实回报。**回退永远允许**（「分镜返工要能只重做第 7 个镜头」）。

## 5. 界面

### 5.1 布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏   导演工作台  作品 ▾   状态灯(FAIL/WARN/未体检/通过)   构思  刷新  设置 │
├──────────────────────────────────────────────────────────────────────┤
│ 阶段条  创意 · 大纲 · 角色 · 剧本 · 分镜 · 生成 · 验收 · 装配 · 交付         │
├──────────────────────────────────────────────────────────────────────┤
│ 导航 │ 主区（随阶段/导航变化）                     │ 右栏（按需出现）     │
│ 首页 │                                            │ 镜详情 / 构思会话    │
│ 工作台                                             │                      │
│ 规范 │                                            │                      │
│ 资产 │                                            │                      │
│ 台账 │                                            │                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.2 首页

进入工作台时，如果没有作品，或者选中的作品**还没开始设计**（0 场 0 镜、简报为空），
先看到首页：

- 一段产品说明与两个入口（**进入工作台** / **新建作品**）；
- **作品卡**：标题 · id · 当前阶段 · 场数 · 镜数，点一下切换作品；
- **新建作品**：按数据契约建一个空骨架（七个状态文件 + 空简报），id 只允许小写字母、
  数字与连字符。

作品一旦有了内容，首页自动让位给工作台；品牌图标与左侧导航「首页」随时可以回来。

### 5.3 九种阶段视图

每个阶段有自己的呈现，不是一个网格套九个阶段：

| 阶段 | 视图 |
|---|---|
| 创意 | 简报文档（Markdown 渲染）+ 作品元信息；可切到编辑 |
| 大纲 | 场次卡片：标题、这一场发生了什么、结束时什么变了、功能、时长、在场角色、拍数 |
| 角色 | 角色卡与道具卡；**每张参考图自带它的生图提示词、尺寸、来源、状态** |
| 剧本 | 场次条 + 逐拍的编辑器（动作行 / 这一拍是 / 台词 / 语气），带增删改移与体检结论 |
| 分镜 | 镜头表（镜号 / 标题 / 内容 / 时长 / 运镜 / 画幅 / 光），点开可编辑 |
| 生成 | 生成台：按场次的**镜头墙** + 镜详情；另有「总览」模式 |
| 验收 | 每镜一张卡：技术判定、实测参数、**人工判定 / 复核人 / 人工发现的问题** |
| 装配 | 版本清单（每镜当前版本、音轨有无、费用）+ 缺口 |
| 交付 | 成片登记与阻塞项 |

### 5.4 生成台

- **按场次渲染**（一次一场，另有「总览」表），所以几十上百镜的作品也不卡；
- 场次条：`SC01 · 6镜 · 状态灯`，可上一场 / 下一场 / 直接跳；
- **镜头卡**：静帧（关键帧或从视频抽帧，抽过就缓存）+ 镜号 + 状态角标 + 标题 +
  **两行内容摘要** + 时长 / 运镜 / 画幅；
- 没有静帧时画**排版封面**（巨大镜号 + 运镜），不留白块；
- 筛选：全部 / 问题 / 未生成 / 已生成；还能按镜号、标题、内容搜索。

### 5.5 镜详情（分镜与生成阶段）

右侧一栏，从上到下是「输入 → 参照 → 判定 → 依据」：

| 区 | 内容 | 性质 |
|---|---|---|
| **镜头** | 运镜 / 画幅 / 分辨率 / 时长（都有预置 chip，另有「自定义…」）、光参数、标题、这一镜的动作、批注 | 真源，可改 |
| **表演** | 该镜覆盖的 beats（动作行 / 台词 / 语气），带增删改移 | 真源，可改 |
| **批注** | 导演对这一镜的话 | 真源，可改 |
| **提示词** | 六段式提示词；可编辑、可「重新编译」、可「校验过期」、可「丢弃手工改写」 | 产物 |
| **判定** | 各体检层的逐项结果（指标名、当前值、判定线）与问题清单 | 只读 |
| **参照** | 参考图缩略（点击开查看器）+ 视频播放器 | 只读 |
| **规则** | 此刻对这一镜生效的规则与依据 | 只读 |

**预置只是方便，不是限制**：画幅、分辨率、运镜、时长都是「点一下就生效」的
标准值，不满足时一律可以手填。

### 5.6 构思会话（AI）

右侧的另一栏，是一个**真实的 AI 会话**，不是插件自己画的聊天框：

- **这一栏常驻**：首页和 conceive 阶段它都在那儿，不用先点顶栏图标把它「唤出来」；
  屏幕挤不下时可以用顶栏图标或窗角的 × 收起，随时再展开；
- **会话由你发起**：进到这个阶段**不会**自动开始聊天——侧栏里点「开始对话」，
  才真的开一段会话。你说的第一句话，就是这场对话的开头；
- 真模型、真工具、真技能——它加载 `drama-conceive` 技能，**能把创意写进
  `creative/brief.md`**；
- **会话挂在 DSH 的工作区下**，和用户自己开的会话没有区别，侧栏里找得到；
- 会话 id 记在作品的 `state.json` 里，所以关掉 DSH、隔天回来还是同一段对话；
- **开场白第一行是 `@workspaces/<work-id>/`**，并明说「只读写这个目录、不要混用
  别的项目」——所有作品共用一个工作区，这一行用来**防止串台**；
  新项目还会额外说明「这是刚建的新项目，目录还是空的」。
  开场白是**上下文**不是发言：它搭在你说的第一句话上一起送到模型那里，
  所以界面上只看得到你说的话；
- **新对话**：收掉当前会话、开一段新的；旧会话不删，仍留在 DSH 的会话列表里；
- **完整对话**：一个按钮跳回 DSH 自己的对话面板，工具卡片、推理过程、审批都在那边。

这个会话在**首页**和** conceive 阶段**都在，因为「想创意」是持续的过程：
想 → 写简报 → 改简报，都在同一段对话里继续。

### 5.7 规范 / 资产 / 台账

| 视图 | 内容 |
|---|---|
| **规范** | 铁律（`R1…R20`）及其依据与适用阶段；创作宪法；数据契约；验收清单。**规则正文从规范文件解析，界面不复述** |
| **资产** | 只增不删的登记册：类型、状态（含作废）、被引用的镜数、尺寸、体积、路径；缺失的文件会被标出来 |
| **台账** | 每条生成任务的轨迹（提交 → 运行 → 完成/失败）、模型、时长、费用；合计与预算 |

### 5.8 设置抽屉

从右侧滑出，**宽度可拖动**（320–900px，记忆在浏览器里）：

| 分组 | 内容 |
|---|---|
| **路径** | 项目根 / 产物位置，各有「选择…」按钮（宿主有原生文件夹对话框就用原生的，没有就用内嵌浏览器）；并写明**为什么是这里** |
| **模型** | 规范模型适配（规则分层里的那一份）；生成模型（提交生成时用谁）；宿主模型（这个工作台自己用谁思考） |
| **刷新** | 自动刷新间隔；0 = 关闭轮询 |

模型列表读的是**宿主已经配好的模型路由**，插件不另存一份 API key。
宿主的模型目录不一定公布，所以模型 id 允许手填。

## 6. 判定与颜色

### 6.1 五色状态

网格与角标只用这五种，**颜色就是体检器自己的判定**，插件不另立标准：

| 色 | 含义 | 判据 |
|---|---|---|
| 灰 | 未生成 | 台账无记录 |
| 蓝 | 已生成未体检 | 有产物，无报告 |
| 黄 | WARN | 主判据过、次判据未过 |
| 红 | FAIL | 任一 FAIL 线未过 |
| 绿 | 通过 | 全部判定线过 |

### 6.2 依据与结论同屏

不只说「FAIL」，要说清**哪个指标、当前值多少、判定线多少、差多少**。
这些数字由**体检器**给出，插件只负责显示，**不复述阈值**：
阈值只有一处真源，改一处即全局生效。

### 6.3 体检器

三类，都是随插件分发的脚本，界面与 agent 调的是同一份：

| 体检器 | 检查什么 |
|---|---|
| 剧本表演层 | 反应拍覆盖率、否定式表演、台词拍缺语气 |
| 画面运动层 | 近乎静止帧比例、有效运动帧、方向平滑、相机位移 |
| 参考图质量 | 饱和度、明度、低饱和区、色彩贫富 |

体检器不可用时**明说不可用**，不编造判定。

## 7. 性能与手感

> 插件嵌在别人的主应用里。插件慢一点，用户会说「DSH 卡了」——
> 而且这类问题不会报错，只会让人觉得整个应用变慢。所以性能是红线。

| 措施 | 效果 |
|---|---|
| 一次刷新只发一个请求 | 顶栏 + 网格 + 阶段条 + 设置一次给全 |
| 数据没变就不重渲染 | 每个视图带版本号，没变就跳过 |
| 面板不可见就停轮询 | 藏起来立刻停，重新可见时补一次刷新 |
| 生成台按场次渲染 | 几十镜的作品也只在 DOM 里放一场 |
| 慢查询有缓存 | 磁盘余量、资产体积这类慢变的数用几秒的 TTL |

**手感**：动效 120–220ms、克制；图片查看器支持拖动平移、以光标为锚点缩放、
双击在「适应窗口 / 1:1」之间切换；编辑即存（不设保存按钮），
但派生字段会明确标出「会被重新编译覆盖」。

## 8. 硬边界（明确不做）

| 边界 | 原因 |
|---|---|
| **不发起付费生成** | 生成由 agent 走幂等三步：**台账 → 提交 → 立刻回写**。接口没有幂等键，重复提交就是重复扣费 |
| **不直接写派生字段** | 它们由编译生成，手改会被覆盖 |
| **不自己实现编译与体检** | 那会造出第二套逻辑，正是要消除的分裂 |
| **不缓存业务状态** | 状态从磁盘派生，缓存靠文件的修改时间失效 |
| 不建第二套规则 | 规则只有一处真源 |
| **任何图片显示前，最长边 ≤1200px** | 大尺寸多脸拼图会被输入审核判为敏感，**永久卡死会话**（真实发生过）。这条是组件级强制约束，不是文档备注 |

## 9. 快捷键与细节

| 键 | 作用 |
|---|---|
| `/` | 聚焦搜索 |
| `J` / `K` | 下一镜 / 上一镜 |
| `Esc` | 关闭浮层、对话框、抽屉 |
| `Enter` / `Shift+Enter` | 构思会话：发送 / 换行 |

- 所有浮层（图片查看器、抽屉、菜单）都能用**点背景、点关闭、按 Esc** 三种方式关掉；
- 空状态、错误状态、加载态都有话可说，不留白屏。

## 10. 尚未提供

如实列出，避免误以为有：

- 场景 / 镜头的**增删与重排**（字段级改动都有，结构变更没有）；
- 在插件里**提交付费生成**（按设计永远不做，交给 agent）；
- 资产的**上传 / 重命名 / 归档**；
- 「让 agent 按这条批注重出这一镜」的一键注入（目前靠构思会话里直接说）；
- 第二个模型适配器（等真的要接第二个模型时再抽适配层——
  只为一个模型设计抽象层，往往会设计错）。

## 11. 术语表

| 术语 | 含义 |
|---|---|
| **真源** | 人可以直接改的原始数据；派生与产物都从它算出来 |
| **派生字段** | 由真源计算出来的字段（如 `description_en`），只读 |
| **产物** | 可以被丢弃并重新生成的中间文件（如提示词 `.txt`） |
| **体检器** | 随插件分发的脚本，负责判定；阈值只存在于这里 |
| **铁律** | 从实测里得出的不可违反项，编号 `R1…R20`，按阶段适用 |
| **台账** | 每次生成提交与花费的记账，是幂等三步的载体 |
| **幂等三步** | 提交前先落台账 → 只提交一次 → 立刻回写结果。接口无幂等键，靠流程保证 |
| **作品** | 一部短剧，一个自包含目录 |
| **总根** | 所有作品的上层目录，同时是唯一的 DSH 工作区 |
| **阶段** | 九个固定步骤之一，每个有唯一出口产物与前置条件 |
