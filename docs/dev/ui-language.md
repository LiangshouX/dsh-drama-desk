# 界面物质语言

工作台的视觉系统写在 `src/client/30-theme.js` 的 `CSS` / token 里（拼进 `client.js`）。
它不是「随便调调」，是一套有纪律的**物质语言**。改界面前先读这篇，
再看 `rendering.md`。

---

## U1 四套字，各司其职

| 角色 | 字族 | 用在哪 |
|---|---|---|
| 仪表 `--f-gauge` | Bahnschrift（DIN 骨架） | **纯拉丁**的编号、微标签、单位（SHOTS / DURATION / FAIL） |
| 正文 `--f-ui` | Segoe UI Variable → Noto Sans SC | 界面文字与中文标题 |
| 读数 `--f-mono` | Cascadia Mono | 镜号、秒数、路径、金额、表格数字 |
| 文学 `--serif` | Noto Serif SC | **只有**简报、台词、场次名、镜名这类「作品内容」 |

规则：**中英混排时 Latin 与 CJK 各取所长**，不要用同一族硬扛。仪表字体只出现在纯拉丁
的地方——给中文套 .16em 字距是有意的，不是失误。

## U2 深浅靠光影，不靠「亮一点」

每一层表面都有**顶光**（`inset 0 1px 0 var(--hl)`）与**落影**。亮色主题顶光弱、落影重；
暗色主题顶光一线冷白、落影更深。**没有顶光的卡片就是一张纸。** 新增任何带边框的块，
都要带上顶光。

## U3 信号盘是导播台自有的

```
红 = FAIL   琥珀 = WARN   绿 = PASS   青 = 在途/未体检   空 = 未生成
```

它们**刻意不与宿主 UI 的强调色同族**（宿主 link 是蓝的）。灯是给人从远处一眼读的，
不能和链接、悬停、选中混在一起。

> **两套词不要混。**
> `shot.status` 是**生产状态**（pending/submitted/succeeded/failed/verified），
> `shot.qc.verdict` 是**体检判定**（PASS/WARN/FAIL）。
> 灯的颜色跟**判定**走，生产状态只决定「还没拍」还是「拍了还没验」。
> 客户端的 `shotSignal(shot)` 就是这个映射，别在别处再写一遍。

## U4 能用形与位说清的，不写小字说明

- 阶段进度是一条**被点亮的轨道**（`.dd-link.lit`），不是几个彩色圆点。
- 右栏没有选中镜头时给**场次概览**（`.dd-sheet`），不是「在网格里点一镜」。
- 阶段标题条与工具条**合成一条**（`.dd-deck`），不要又加一条横栏。
- 眼下的例外：`.dd-deck-id .sd3` 那句阶段说明，窄台面（<1240px）自动隐藏。

## U5 旧 token 名是别名，不是第二套体系

`--r-sm` / `--card` / `--accent` / `--draft` 这些名字还在，但它们是**指向新体系的别名**
（见 `CSS` 里的「兼容别名」块），行内样式还在用它们。**新写代码用新名字**
（`--rx-*` / `--raised` / `--hot` / `--sig-*`）。

## U6 改东西只有一种手势：右上角 ✎，原地改，显式存

整个工作台的文本编辑统一由 `src/client/41-editing.js` 的 `Editable` 承担。规则：

| | 规则 |
|---|---|
| **点内容不进编辑** | 进编辑只有一个入口：内容右上角那枚 **✎**（常驻、默认 45% 透明度、悬停变亮）。点那段字什么都不发生——「点一下字就进编辑」看着聪明，实际是误触陷阱：想选一句台词复制，结果进了编辑态，再点别处又得决定保存还是丢弃。 |
| **单行 vs 多行，两种形态** | **单行字段**（音色 / 时长 / 标题）展开成一行小控件（28px）＋ ✓ / ✕ —— 那就是它的尺寸。**多行字段**展开成一块**编辑面**：头部 `预览 \\| 编辑 · N 字 · 未保存 · 保存 · ✕`，正文按态切换。 |
| **编辑面 = 最佳实践的那套东西，只是不装弹窗** | 长期记忆《文本编辑组件最佳实践》里的十条规则（两态切换、尺寸恒定、字数、显式保存、未保存拦截、保存分流内联）照搬；**载体**从弹窗换成原地展开。用户明确否掉了「点击 → 弹出窗口」这个动作。 |
| **两态尺寸恒定** | 预览与编辑**共用同一个高度**（打开那一刻定下：`clamp(4 行, 读态高度, 视口 85%)`），切换时盒子**一动不动**。实测：简报读态 669px → 编辑面 621px ＋ 头部，切预览/编辑均为 621px。 |
| **预览 = markdown，编辑 = 保真源码** | 编辑态是等宽、`pre-wrap`、不 trim 不格式化的源码；预览态走 `MarkdownLite`（与读态同一个渲染器）。提示词这类**产物**用 `markdown:false` 保持原样。 |
| **只有【保存】才写盘** | **失焦不存**——焦点离开只是焦点离开，不是一个决定。键盘路径：单行 Enter、多行 Ctrl+Enter。Esc 取消。 |
| **没改动就没有可点的保存** | `disabled` 而不是隐藏：按钮在、但不可点（消失会让人以为功能没了）。头部同时挂「未保存」胶囊。 |
| **未保存关不掉，但一定给出路** | 有改动时点 ✕ / Esc → 头部下方出现警告条（`放弃修改` / `保存`），编辑面不关。 |
| **存不上就留在原地** | `onSave` 返回 `false` = 没存上：留在编辑态、草稿一字不丢，行内给一句「没存上，改动还在」。 |
| **只读** | 派生字段与机器读数用 `readOnly`：不假装可编辑（没有 ✎、没有悬停、没有手型光标）。 |

> **为什么不是「编辑 → 保存」两段式按钮行**：那要求用户每改一处就**再点一次按钮**。一次
> 大纲有 72 个字段，每场 6 个；两段式意味着一次审阅要点几十次按钮，而按钮把一屏大纲
> 吃掉一半。现在「改一处」= 点 ✎ → 改 → 点保存，且**只有真的改了**才有第二步。

**推论（写新界面时照着做）：**

- 新增可编辑字段**一律用 `Editable`**，不要再写「读态 div → 编辑态 input → 保存 /
  撤销按钮」那一套。
- **只有真正需要「一次改多处再统一提交」的地方**才用表单 + 提交按钮（设置抽屉就是）。
  逐字段修改的场景不要用表单。
- 改文案要改**标签本身**（`label` + `labelTitle`），不要在标签旁边再补一句说明。
- **别再手写第二套编辑器**：`ConceiveView` 与 `PromptEditor` 各写过一套
  （textarea + ✓/✗），它们是被消灭的对象。
- **别再弹窗改文本**：多行字段的编辑面就在原地。浮层只留给**看**（图片 / 视频）。

> **契约上的一个坑：`beat.mode` 与 `beat.delivery` 必须同时满足。**
> 数据契约 §6 规定台词拍必须有语气阶梯（`delivery` 非空）。所以用户点
> 「画内音 / 画外音」时，若语气还是空的，**mode 先不落盘**——等语气填上了，mode 与
> 语气一起存。否则用户会先撞上一句 Host 的报错，而界面上又没有地方让他补语气。

## U7 品牌标记：胶片三格

标记是**一条胶片**：厚片身、顶边四枚片孔、中间三个画格——**中间那格亮着琥珀色**，
正是正在产的那一镜。

| 位置 | 形态 | 颜色 |
|---|---|---|
| 插件图标 `icon.svg` | 64 网格 · 彩色 | 冷蓝 `#2F6BE0` 片身 + 暖琥珀 `#F5A524` 在产的那格 |
| 工作台顶栏 `DramaDeskMark` | 64 网格 · 彩色 | `var(--brand-blue)` + `var(--brand-amber)` |
| 侧栏字形 `DramaDeskIcon` | 64 网格 · **单色减法** | `currentColor` |

**三处同源，但侧栏是「减法」不是「缩小」。** 侧栏只有 16px：胶片的片孔在那里会糊掉，
整条片子变成一块深色方块（比邻居的线描重得多）。所以侧栏只画**那三格**——两头空心画格，
中间一个实心。改形状要三处一起改：`src/client/` 里的 `FILM_STRIP` / `FILM_FRAME` /
`FILM_GRID_L|M|R` 与 `icon.svg` 是同一套坐标。

**三条纪律：**

- **标志是产品的一部分，不随主题换色。** `--brand-blue` / `--brand-amber` 是**常量**，
  不是语义 token，别把它们塞进暗色/亮色的覆盖块里。
- **同一枚 SVG 要在亮底与暗底都立得住。** 所以不用深色底板（在插件列表的暗底上等于
  隐形），镂空是真透明而不是拿背景色去挖。
- **镂空用 evenodd 子路径，不用 `<mask>`。** 插件管理器把 `icon.svg` 当
  `data:image/svg+xml;base64,...` 塞进 `<img>`——那是**独立 SVG 文档**，mask 在那条路上
  不保险，路径填充稳。

> 顺带一条经验：**别信 SVG 直接放大。** 浏览器会重新插值，看着清楚，栅格化成 16px
> 真像素后可能是一团噪点。判断小尺寸可读性要 **canvas 栅格化后放大**。

## U8 验收

```bash
node scripts/build.mjs --check        # 语法 + 运行时形状 + 等价性回归
node scripts/render-probe.mjs --base http://127.0.0.1:<宿主端口>
node scripts/perf.mjs --base http://127.0.0.1:<宿主端口>
```

改完界面**必须截图看一眼**（`scripts/shot.ps1`），并且**看控制台**：`rendering.md`
里的坑，症状都是「DOM 在、几何对、就是不画」或「一片空白」，自动化断言查不出来。
# 侧栏的空间约束（v0.2.1）

布局按导演工作台自身宽度测量，宿主侧栏不算可用空间。主区保留至少 360px；两块侧栏放不下时，制作助手与镜详情只展开一块。打开镜头优先显示镜详情，打开制作助手优先显示会话，已选镜头保留。

工作台窄于 760px 时，侧栏改为可关闭的覆盖面板；未选镜头时不自动弹出场次概览。拖拽宽度要扣除导航和其他已展开侧栏，不能把主区挤成 0px。窗口缩小不覆盖用户保存的首选宽度。
