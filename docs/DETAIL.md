# 导演工作台

把 AI 短剧生产流水线里那些只存在于代码、JSON 和 agent 脑子里的规范，
变成一个**人能读、能改、能做取舍的工作台**。

> 一句话：流水线网格上的每一格，颜色就是体检器自己的判定；
> 点开一镜，**依据与结论同屏**——不只是「FAIL」，还有「0.279 < 0.28，差 0.001，
> 来自哪次实测」。

---

## 它能做什么

入口在**左侧栏的插件区**（与「自媒体工作台」同级），点开是一整块工作台：

| | |
|---|---|
| **⊞ 流水线** | 行=场次、列=镜头的网格；一格一色 = 该镜的体检状态；顶部阶段条可点，**推进前先看前置条件与缺口**；筛选（全部 / 失败项 / 已生成）、密度切换、搜索；快捷键 `1–9` 切镜、`J/K` 上下、`/` 搜索、`F` 聚焦失败项 |
| **◈ 镜详情** | 从左到右是「输入 → 参照 → 判定 → 动作」：**镜头字段**（时长/运镜/光参数/比例，真源，就地编辑）、**表演**（beats 的动作行/台词/语气，真源，就地编辑）、**批注**（落在该镜的 notes，真源）、**提示词**（六段产物，只读 + 重新编译 + 校验过期）、**参照**（参考图缩略图 + 成片视频播放器）、**判定**（四个体检器的逐项结果）、**规则**（此刻生效的规则 + 依据） |
| **◈ 规范** | 铁律 R1–R20 及其依据、创作宪法、数据契约、验收清单——**从 `build/spec/` 解析，不复述** |
| **▣ 资产** | 资产索引：状态（含 `deprecated` 与作废原因）、引用关系、存储占用、缺失文件 |
| **⌘ 台账** | 幂等三步的记账轨迹：任务、状态、费用、耗时、产物链接 |
| **设置** | 项目根 / 产物位置（可改，写进 profile 自己的 patch 层）、规范模型适配、宿主当前模型；并**说明当前路径为什么是这个** |

**它不做**：不发起付费生成（生成仍由 agent 走幂等三步）、不自己实现编译与体检、
不复制规则、不写派生字段。

---

## 一个操作，两个调用者

界面上的每个动作和 agent 的每个工具**调同一个 Host service 方法**：

| 操作 | 界面 | agent tool |
|---|---|---|
| 读流水线 | 网格 | `drama_desk_status` |
| 读镜详情 | 镜详情 | `drama_desk_shot` |
| 读体检 | 判定区 | `drama_desk_qc` |
| 读规则与依据 | 规范视图 | `drama_desk_rules` |
| 读资产 | 资产视图 | `drama_desk_assets` |
| 读台账 | 台账页 | `drama_desk_ledger` |
| 读 / 推进阶段 | 阶段条 | `drama_desk_stage` |
| 读 / 改设置 | 设置抽屉 | `drama_desk_settings` |
| 改表演（beats） | beats 编辑器 | `drama_desk_edit_beat` |
| 改镜头参数 | 镜头字段 | `drama_desk_edit_shot` |
| 写批注 | 批注区 | `drama_desk_annotate` |
| 重新编译 | 按钮 | `drama_desk_compile` |
| 校验产物是否过期 | 角标 | `drama_desk_check` |

所以人和 agent 对「合不合格」的判断**必须一致**——否则插件就是新的信息分裂源。

## 阶段与前置条件

阶段条上的每一段都可以点。点开是**契约自己的话**：

- 前置条件：来自数据契约 §11.2 的原文（插件解析，不复述）；
- 缺口：具体到「镜头 SC02-SH01 没有登记视频资产」；
- 正向推进被缺口拦下；**回退不校验**（契约明写：分镜返工要能只重做一个镜头）。

## 配置

在 profile 的 `cordis.patch.yml` 里改（这一层不会被插件升级覆盖）：

```yaml
- id: drama-desk
  name: 'dsh-drama-desk'
  config:
    projectRoot: 'D:/Code/MyDrama'     # 从哪里发现作品（留空 = 自动）
    outputRoot: ''                     # 产物落点（留空 = 自动跟随「视频」已知文件夹）
    model: 'minimax'                   # 规范分层里的模型适配 id
```

也可以在**设置抽屉**里改：插件通过 Host 的配置编辑器写进 profile 自己的 patch 层，
改完插件重启即生效。

**「留空」是有意义的，不是没填。**

- `outputRoot` 留空 → 插件读 **Windows 的「视频」已知文件夹**
  （`FOLDERID_Videos`，跟随资源管理器的「位置」重定向）。
  你把视频目录搬到 D 盘，插件就跟着搬到 D 盘；产物**不会**悄悄落回系统盘。
- `projectRoot` 留空 → 先找当前会话工作目录，再找产物位置旁边的目录；
  都找不到才用 DSH 的默认工作目录。
- 界面「设置」页会写清**当前解析到哪个路径、为什么是它**，并在路径落在系统盘时
  **给出提醒**——成片很占地方，系统盘会被不知不觉撑爆。

## 已知限制

- 体检器需要 Python。`beat_qc.py` 只用标准库，开箱可用；`image_qc.py` 需要
  Pillow + numpy，`motion_qc.py` 还需要 numpy 与 ffmpeg。**缺依赖时界面明确
  显示「体检器不可用」并给出原因，不会编造判定。**
- 提示词编译调用**作品自己的** `prompts/compile_prompts.py`（六段式写法是
  模型/作品专属的，不属于插件包）；作品没有时回退到插件包内的驱动脚本。
- 图片一律经由插件的 `/drama-desk/image` 路由显示，**最长边 ≤1200px**。
  这是一条出过事故的硬约束：大尺寸多脸拼图会被输入审核判为敏感并**永久卡死会话**
  （已发生 3 次）。超过上限的图会先缩放；缩放器不可用时**拒绝显示**，而不是放行原图。
- 视频经由 `/drama-desk/video` 路由播放（带 HTTP Range，可拖动进度）。
- 宿主半边不热重载：改 `src/host/**` 要等 DSH 重启才生效。
