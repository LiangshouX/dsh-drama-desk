# drama-outline — 结构与场次

**本阶段唯一产出**：`workspaces/<work-id>/scenes.json`（场次表）。

上一阶段给了你一个内核。这一阶段把它变成**一串有先后、有功能的场次**。

你不写台词、不写镜头、不设计角色外观。

---

## 0. 开工前

```bash
python tools/drama/drama.py next --work <work-id>
python tools/drama/drama.py constitution
python tools/drama/drama.py template scene-table
```

**先读 brief 的「待确认」**：标注「outline 前定」的条目**必须现在解决**——带着未定的动机去分场，分出来的场次一定是废的。解决不了就退回 conceive，别硬分。

---

## 1. 三步顺序：转折点 → 场次 → 时长

顺序不能颠倒。先定转折点再切场次，否则会切出一堆各切各的场。

### 第一步：先定转折点

三幕各有一个转折点，每个用一句话说清**什么变了**：

| 转折 | 回答的问题 |
|---|---|
| 第一幕 → 第二幕 | 主角失去了什么 / 发现了什么 |
| 第二幕 → 第三幕 | 代价变成了什么 |
| 第三幕 → 结尾 | 最终做了什么选择 |

**写不出转折点就别往下走。** 转折点定不下来，说明内核还飘着——回 conceive 补。

转折点之间要形成**因果链**：A 的转折直接导致 B 的转折。若两个转折互不相干，中间缺一场。

### 第二步：按转折点切场次

**一场 = 一个功能。**

| 功能 | 作用 |
|---|---|
| 建置 | 让观众知道这是谁、这是什么、有什么不对 |
| 升级 | 阻力变大，代价开始显形 |
| 揭示 | 观众知道了一件角色还不知道的事（或反过来） |
| 转折 | 局面改变，回不去了 |
| 收束 | 情绪落地，回应内核 |

切场次的两个判据：

- **一场只推进一个要素。** 推进两个 → 拆成两场，或砍掉一个。
- **一场结束时有变化。** 没有变化的场次是废场次，删掉或合并。

### 第三步：分时长预算

```
总时长（brief 里）÷ 场次数 ≈ 每场平均秒数
```

但平均是假的。实际分布：

- **第一场最短**（前 3 秒抓人，别铺陈）
- **转折场最长**（信息量大、情绪要转）
- **收束场中等**（留白也是内容，别赶）

给每场写 `duration`，总和落在总时长 **±15%** 内。**写完把总和报给用户看**——超了就说明打算砍哪场，不要默默超支。

## 2. 场次表字段

见 `python tools/drama/drama.py template scene-table`。

必填：`id` / `act` / `title` / `function` / `duration` / `summary` / `characters`。

**`characters` 填角色 ID**（小写英文，如 `aling` / `shopkeeper`）。ID 在本阶段就定好——characters 阶段沿用同一套，不改名。这样一条链下来不用反复翻译。命名见 `docs/数据契约.md`。

`beats` 留空数组，那是 script 阶段填的。

---

## 3. 检查清单

- 每场能用**一句话**说清发生了什么？
- 每场都有 `turn`，或明确它不承担转折功能？
- 三幕转折点构成因果链吗？
- 时长总和在预算内吗？
- 角色出场分布合理吗？（连续三场同一个人独白 = 节奏塌了）
- 前 3 秒有钩子吗？（短视频的生死线）
- brief 的「设定规则」在结构上自洽吗？（超现实设定尤其容易在第二幕崩）

---

## 4. 落盘与交接

```bash
python tools/drama/drama.py scenes write
python tools/drama/drama.py advance --stage characters --note "场次表完成：N 场 / M 秒"
```

---

## 5. 边界

- **不写**台词、不写景别机位、不设计角色外观。
- **场次不是镜头。** 一个场次会拆成 2–5 个镜头，那是 storyboard 的事。
- brief 里没定的设定**不要自己发明**。需要新设定才能自洽 → 退回 conceive 先补简报。
- 不在这里讨论成本与提示词。
