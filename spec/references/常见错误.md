# 常见错误与排除路径

> 按"症状 → 原因 → 修法"组织。多数条目来自实测。

---

## 1. 画面状态不对（人物没湿 / 穿错衣服 / 白天变夜晚）

### 1.1 最常见：提示词内部矛盾 ⚠️

**症状**：参考图是湿身，提示词也写了 "dark and wet"，但生成的是干身。

**原因**：`subject_definitions` 里把主体写成干身（如 "wearing a **washed-out light khaki**
cotton jacket"），`detailed_description` 里写湿身 —— 同一段提示词自相矛盾，模型取了前者。

**实测证据**：SH01 干身。改对 `subject_definitions` 后，T1/T2/T3 全部湿身，
参考图怎么配都正确。

**修法**：
1. 对照检查 `subject_definitions` 与 `detailed_description` 的所有状态词
2. 重点核对：wet/dry、day/night、季节、受伤/完好、着装
3. 两处必须一致

### 1.2 混合了互斥状态的参考图

**症状**：同一镜头喂了 wet + dry，模型偏向其中一个。

**说明**：实测（T3）证明这**不是**致命因素——只要写消歧句，混合也能得到正确湿身。
但仍不建议混用，因为模型行为不稳定。

**修法**：
- 首选：同镜头只用同状态参考图
- 必须混用时写消歧句：
  ```
  <Picture 2> shows the same man dry and is used only to confirm his facial identity;
  none of the dry clothing, dry hair, or dry skin of <Picture 2> is applied.
  ```

### 1.3 参考图本身状态不明确

**症状**：模型把干身角色的图当成了通用身份图。

**修法**：状态命名要显式（`cellist_wet_full.png` 而非 `cellist.png`），
参考图本身要能一眼看出状态。

## 2. 没有口型 / 口型不明显

**症状**：有台词音，但人物闭着嘴。

**原因**：**九成是提示词写法问题，不是模型能力问题。**

官方 voiceover 写法包含：
```
says in a calm off-screen voiceover: <d>[Chinese] ...</d>
Immediately after the complete <d> block, his lips remain completely closed ...
```
"lips remain completely closed" 是明确闭唇指令。

**实测证据**：SH01 口型不明显、T1 不太明显、T2/T3 彻底没有——四条提示词都含这句。

**修法**：
- 要口型 → 改写成画内音，**删掉** "off-screen voiceover" 和 "lips remain completely closed"，
  改为 "His lips move clearly with the words as he speaks."
- 要画外音 → 保留官方写法，并明确说明画面中角色嘴唇不动
- 写完自查：提示词里有没有 "voiceover" 或 "lips remain closed"

---

## 3. 道具细节丢失或跑错位置

**症状**：贴纸/标志不见了，或跑到画面里别的物体上。

**实测证据**：T2 中琴身的白花贴纸跑到了**背景路灯柱**上。SH02 用两张参考图则还原准确。

**原因**：参考图里该道具的角度偏远/背对镜头，模型辨识不出，挪到了更清晰的位置。

**修法**：
- 道具特写镜头**单独准备一张该道具的清晰参考图**（正面、光照好、占画面大）
- 在 `subject_definitions` 里明确描述道具特征（颜色、贴纸位置、材质）
- 不要只靠人物全身图带出道具细节

---

## 4. 生成速度与预期不符

### 4.1 实际比文档快得多

**实测**：H3 768P 5s 约 **1.5–2.2 分钟**，而官方文档称 15–30 分钟。

**影响**：
- 单会话可完成 10–15 个镜头
- 不必设计成"提交完就结束会话"
- 仍不建议一次提交 30 个以上（并发排队会拉长总时长，中途失败难归因）

### 4.2 提交后无响应

**排查顺序**：
1. 查台账 `drama task list` —— 是否已写入 task_id
2. 用 task_id 直接查询 provider
3. **确认没有重复提交**（H3 无幂等键，重复提交=重复扣费）

## 5. 验收阶段

### 5.1 机器判定与实际不符

**症状**：视频理解说"镜头静止"，实际是推近。

**实测证据**：SH01 被判 "Static"，逐帧对比证明是缓慢推近；
T1 判 "Static" 而 T2/T3 判 "slow push-in" —— 同一模型判定不自洽。

**修法**：
- 技术参数（时长/分辨率/比例/编码/响度）用 ffprobe 自动判定，**可作判废依据**
- 语义判定（相机运动/年龄/情绪/口型/一致性）**只作参考**
- **人工看首/中/尾三帧**才能定稿

### 5.2 音量为 0

**判定**：`mean_volume < -45dB` → 无声废片。

**实测参考值**：
- 有对白的镜头：-14 ~ -19 dB
- 纯环境音镜头：约 -29 dB

### 5.3 废弃了能用的片子

**症状**：看到机器判"年龄不符"就判废。

**说明**：参考图人物本身就偏少年相，模型跟着走是**正确的**——
它忠实还原了参考图。问题在参考图，不在生成结果。

**修法**：要成年角色就换参考图，或在提示词里强化年龄描述。

## 6. 提示词被截断或报错

| 症状 | 原因 | 修法 |
|---|---|---|
| 提交报参数错误 | prompt 超长或含非法字符 | 长度上限 7000 字符（Unicode 码点），超了先压缩再查 |
| 参考图被拒 | 尺寸/比例/大小超限 | 图片 ≤30MB，宽高 256–5760；首尾帧模式宽高比 0.4–2.5 |
| 参考图数量被拒 | 混合批次超限 | 图/视频/音频合计 ≤12 个；图 ≤9、视频 ≤3、音频 ≤3 |
| keyframe 与参考集合冲突 | 同时传了 `input_image` 和 `reference_images` | 二选一，keyframe 模式不能混用参考集合 |

## 7. 工程问题

| 症状 | 原因 | 修法 |
|---|---|---|
| `SyntaxError: invalid character '：'` | Python 里用了 `//` 注释 | 改用 `#` |
| `FileNotFoundError: WinError 2` | subprocess 调 `.cmd` 包装器 | 加 `shell=True`，用 `shutil.which` 定位 |
| JSON 参数文件解析失败 | PowerShell `ConvertTo-Json` 转义坏了 / 带 BOM | **一律用 Python `json.dump` 生成** |
| 警告被当致命错误 | `$ErrorActionPreference='Stop'` + node 写 stderr | 保持 `Continue` |
| 控制台中文乱码 | GBK 显示问题 | 文件本身 UTF-8 正常，别误判 |
| 写入/删除被安全策略拦截 | bash 递归写入判定 | 用 `write` 工具落盘；删除用顶层 `rm -- <目标>` |

## 8. 参考图阶段：一致性与画风

> 2026-11-08《名字典当行》参考图阶段实测（image-01）。

### 8.1 画风整体跑偏成"暗黑水彩插画"

**症状**：同一批参考图像恐怖片插画，不像手绘赛璐璐动画。

**三个根因**（缺一不可）：
1. 提示词用了暗黑水彩插画语汇（"dark watercolor concept art"、厚涂笔触）
2. 色彩指令与赛璐璐相反（`muted / low-saturation / cool grey-blue shadows`）
3. 脸是写实解剖脸，不是圆润的动画脸

**修法**：画风骨架写死为「人物 = 赛璐璐平涂（flat fills + crisp dark-brown line art, two or three tones of shadow, no visible brush texture），背景 = 透明水彩渲染」；色域写「暖色主导、饱和通透」，并把禁用词直接列进提示词的否定项。

### 8.2 用编辑模式锁一致性 → 反而漂得更远

**实测**：image-01 的 `requests[].image_url` 确实生效（能看出参考图的铜夹位置），但输出把发色从黑茶改成红棕、脸型改成熟、发长过肩——"只改服装"的编辑把脸一起改了。

**结论**：**不要用编辑模式锁同一性**。一致性只能靠纯文本。

### 8.3 纯文本换 state 时，脸会跟着服装一起变

**症状**：写"换成没有围裙的版本"，模型连发型、脸型、年龄感一起重画，还自行换成短裤露大腿。

**修法**：
- 人物外貌句在所有 state 之间**逐字复制**（同一段英文描述，含发型长度、刘海形态、发色、脸型、眼睛、嘴）
- 只改服装句与表情句
- 用显式否定句钉死"没有某物"：`There is NO apron, NO waistband, NO tie, NO sash...`
- 修完必须**人眼看全身图 + 面部特写两张**，与基准 state 并排比对

### 8.4 纯色衣服被画成剪影

**症状**：墨色长衫变成一整块纯黑，看不出体积。

**修法**：提示词里写 `visible soft fold lines in deep blue-black ... not a flat silhouette`，并补 `a faint warm rim light along the shoulders`。

### 8.6 参考图"画风对了但人不好看" —— 审美问题

**症状**：赛璐璐骨架、水彩背景都对了，但角色"丑"——黑豆大眼、粗眉、方下颌、头发一整块死黑、衣服是平涂色块、站桩正面。换成别的模型（GPT-4o image）跑同一段提示词，产出明显更好看。

**根因：提示词在"描述"而不是在"设计"**。触发审美的具体元凶（实测逐条验证）：

| 提示词里的写法 | 实际效果 | 改法 |
|---|---|---|
| `large bright round eyes with clear highlights` | 巨大黑豆眼，眼白消失 → 呆 | `gentle almond eyes, narrow dark irises, visible upper eyelid crease, plump lower lid, long soft eyelashes, one small catchlight` |
| `soft rounded face` + `full-cheeked` | 婴儿肥 → 萌而非美 | `gentle oval face with a softly tapered chin, full but not babyish cheeks` |
| `crisp dark-brown line art` | 粗硬黑边 → 绘本感 | `soft warm-brown outlines of varying thickness, thinner and delicate on the face` |
| `soft transparent watercolor wash in the background` | 背景出现脏色块，且喧宾夺主 | `clean warm off-white background with a single very faint pale beige wash` |
| 只写服装名称 | 平涂色块、没有垂坠 | 补 `natural fabric drape and soft fold lines` |
| 只写发型名称 | 一整块死黑 | 补 `glossy ... with warm chestnut highlights along the crown and the ends, distinct layered strands catching the light` |
| 不写姿态 | 正面站桩、四肢僵直 | 补 `relaxed three-quarter pose, weight on the back foot, arms hanging loosely with softly bent wrists, head tilted very slightly` |
| 不写表情 | 无神 | 补 `calm, warm, slightly wistful expression` + `faint peach blush on the cheeks` |
| 不写审美锚点 | 落入模型默认审美 | 补 `beautiful, elegant and appealing design, art directed by a top animation character designer, award-winning animated feature` |

**删词清单**：`anime`（拉向萌系）、`cute`、`chibi`、`full-cheeked`、`large round eyes`。

### 8.7 image-01 的 `image_url`：既能锚风格，也能锚脸

> 更正 8.2 —— 结论要分情况，取决于"锚什么"。

| 用法 | 实测结果 |
|---|---|
| 编辑模式：拿角色图当参考 + "只改 X" | 脸会漂（发色、脸型、发长一起变） |
| 风格锚：拿一张美图当参考 + "只抄画风，脸重新设计" | 画风继承良好，但**把参考图的脸的缺点也继承了**（死鱼眼、浓黑眉、灰紫调） |
| **角色锚：拿已定稿的脸当参考 + "保持同一张脸，画全身"** | ✅ **一致性和审美都最好**。产出的全身图与特写明显是同一人，且脸比纯文本版本更好 |

**推荐工作流**：
1. 先用纯文本生成"最佳脸"的一张特写（反复抽卡取最优）
2. 以这张特写作 `image_url`，生成该角色的其他全部图（全身、其它 state）
3. 一致性靠"锚定"而非"逐字复述描述"

**纯文本不可靠**：同一段人物描述句在两次调用里会给出不同的脸型与年龄感；`seven heads tall / long legs` 这类比例指令对 image-01 基本无效（它默认输出偏 Q 的比例），要修长只能靠竖构图（2:3 / 9:16）+ "head small in the frame"。

### 8.9 批量图片编码：慢 + 中断会留"半截文件"

**症状**：2K 参考图用 `PNG, optimize=True` 编码，**约 40 秒/张**，20 张要 13 分钟。更坑的是：中途取消编码进程，会留下**写到一半的截断 PNG**——文件存在、大小看着正常，但 `Image.load()` 直接报 `image file is truncated`。

**为什么没被发现**：`drama verify-index` 只比对 **sha256 与字节数**，**不校验图像完整性**。半截文件的哈希照样算得出来，校验照样通过。只有真正拿去当 H3 参考图上传时才会炸。

**修法**：
1. **参考图统一存 JPG**：`im.convert("RGB").save(dst, "JPEG", quality=95, subsampling=0)` —— 体积约为无损 PNG 的 1/4~1/5，编码快 20 倍，H3 对参考图格式无要求
2. **任何批量编码后必须逐张验证**，不能只看哈希：
   ```python
   with Image.open(p) as im:
       im.load()   # 不 load 就发现不了截断
   ```
3. 编码进程不要中途 kill——要么等它跑完，要么分批（每批 ≤5 张）

**实测**：20 张 2K 参考图，PNG 无损 200.6 MB → JPG q95 **61.7 MB**，且揪出了 1 张此前一直混在定稿里的坏图。

### 8.10 道具上的汉字必然是伪字

**实测**：要求刻"十九"，出来的是形似伪汉字；朱砂印文更是一串乱码。

**修法**：接受这一点，不在提示词里死抠字形；改由生成阶段的**特写构图 + 叙述性描述**承担识别度（观众看到"两个被红线连起来的名字"即可）。

## 9. 成本失控

**症状**：额度告急 / 预算超支。

**排查**：
```bash
python tools/drama/drama.py budget --limit 30
```

**常见原因**：
1. 废片率过高（提示词没写对 → 反复重生成）→ 先修提示词，不是加预算
2. 用了 2K 而非 768P（成本 1.6 倍）
3. 参考图传了视频（按输入视频时长额外计费，$0.08–0.143/秒）
4. 重复提交（无幂等键，检查台账）

**预防**：
- 每个镜头**先出草稿再出正稿**（草稿用更便宜的档位）
- `overall_soundscape` / `non_diegetic_music` 写好，避免二次生成
- 提交前跑一遍 `drama verify-index`
