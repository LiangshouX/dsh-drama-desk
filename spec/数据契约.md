# drama 数据契约 v1.2

> 作品产出的内容不乱的前提。所有 Agent、脚本、工具都必须遵守本契约。
> 契约变更需升版本号，并在 `CHANGELOG.md` 记录。

---

## 0. 三层架构

```
<workspace>/
├── .agents/skills/drama-<stage>/   # ① 方法层：每阶段一个独立技能（Agent 读）
├── .drama/                         # ② 记忆层：铁律 / 宪法 / 模板 / 参考（CLI 读）
├── tools/drama/drama.py            # ③ 工具层：CLI（裁决状态与路由）
├── workspaces/<work-id>/           # ④ 产物层：每个作品一个独立目录
└── docs/
```

| 层 | 归谁管 | 规矩 |
|---|---|---|
| 方法层 | Agent | 只写本阶段的做法，不写别的阶段的内容 |
| 记忆层 | CLI | 铁律/宪法/模板的**唯一真源**，CLI 按阶段筛选后注入 |
| 工具层 | CLI | 裁决状态、路由技能、校验前置条件；不发起付费生成 |
| 产物层 | Agent + CLI | 状态 json 由 CLI 独占写入，资产文件由 Agent 产出但必须登记 |

### 0.1 阶段产物链

```
creative/brief.md  →  scenes.json  →  characters.json  →  shots.json  →  视频资产
   conceive            outline         characters          storyboard       generate
```

每个阶段都有**唯一的结构化出口**，下游读上游产物而不是靠回忆。出口清单：

| 阶段 | 出口 | 写入方式 |
|---|---|---|
| conceive | `creative/brief.md` | Agent 写文件 → `asset add --type doc` 登记 |
| outline | `scenes.json`（场次骨架） | Agent 写文件 → `drama scenes write` 同步 |
| characters | `characters.json`（角色卡+道具卡） | Agent 写文件 → `drama characters write` 同步 |
| script | `scenes.json` 的 `beats[]` | Agent 改文件 → `drama scenes write` 同步 |
| storyboard | `shots.json`（镜头清单） | Agent 写文件 → `drama shots write` 同步 |
| generate | 视频资产 + 提示词资产 + `ledger.json` | Agent 产出 → `asset add` 登记 |

## 1. 目录结构

### 1.1 工作区根（一个仓库 = 一个工作区）

```
<workspace>/
├── .agents/skills/
│   ├── drama-conceive/SKILL.md    # 阶段技能（已拆分）
│   ├── drama-generate/SKILL.md    # 阶段技能（已拆分）
│   └── minimax-drama/SKILL.md     # 过渡技能：覆盖尚未拆分的 7 个阶段
├── .drama/                        # 记忆层（CLI 读）
│   ├── rules.md                   # R1–R12 唯一真源
│   ├── constitution.md             # 项目级创作宪法
│   ├── templates/                 # 模板覆盖栈的底层
│   │   ├── brief.md
│   │   ├── scene-table.md
│   │   ├── character-card.md
│   │   └── h3-prompt.md
│   ├── presets/                   # 可选：风格预设（presets/<name>/templates/）
│   └── references/                # 按需加载的参考资料
├── tools/drama/drama.py           # CLI 本体（不装包，随仓库走）
├── workspaces/<work-id>/          # 每个作品一个独立目录，互不干扰
├── docs/                          # 项目级文档（契约、决策记录）
├── .tmp/                          # 临时产物，可随时清空（已在 .gitignore）
└── README.md
```

**规则**：
- `workspaces/` 下的每个子目录是一个**自包含的作品**，可单独归档、单独复制、可单独重跑。
- `.drama/` 是**项目级**的；作品级同名文件（如 `workspaces/<id>/constitution.md`）覆盖项目级。
- 记忆层的文件**只读不写**：Agent 不手改 `rules.md` / `constitution.md`，要改就改这里并让 CLI 重新注入。

### 1.2 作品目录

```
workspaces/<work-id>/
├── work.json          # 作品元数据（唯一真源）
├── state.json         # 当前状态机位置（CLI 唯一写入方）
├── scenes.json        # 场次表：SC 编号、场次功能、时长、beats（outline + script 产出）
├── characters.json    # 角色表：角色卡与道具卡（characters 产出）
├── shots.json         # 分镜表：镜头清单与参数（storyboard 产出）
├── assets.json        # 资产索引：所有素材的登记册
├── ledger.json        # 生成台账：任务与消耗
├── constitution.md    # 作品级创作宪法（可选，覆盖项目级 .drama/constitution.md）
├── creative/          # 创意阶段的产出
│   └── brief.md       # 创意简报（conceive 阶段的唯一产物）
├── refs/              # 参考图（角色立绘/道具/场景）
│   ├── <role>_<state>_<tag>.png
├── prompts/           # 提示词（每镜一份，最终稿）
│   └── <shot-id>.prompt.txt
├── videos/            # 生成的视频片段
│   └── <shot-id>_v<NN>.mp4
├── audio/             # 配音 / 音效 / 音乐
├── keyframes/         # 镜头关键帧
│   └── <shot-id>.png
└── verify/            # 验收记录
    └── <shot-id>.report.json
```

**规则**：
- 顶层 7 个 json 是**状态层**，由 CLI 读写，Agent 通过 CLI 命令修改，不直接手改。
- 其余目录是**资产层**，文件可被 Agent 直接创建，但**必须**在 `assets.json` 登记。
- 任何新文件类型都要先在此契约登记，再产出。

## 2. 命名规范

### 2.1 作品 ID `<work-id>`

```
<slug>-<yyyyMMdd>
```

- `slug`：小写字母、数字、连字符，语义化英文短语，长度 3-40
- 例：`rain-cello-20261101`、`neon-alley-20261115`
- 唯一性：同一天多个作品用 `slug-2`、`slug-3`

### 2.2 场次 ID `<scene-id>` 与镜头 ID `<shot-id>`

**场次 ID**（`scenes.json` 的 `id`）：

```
SC<NN>
```

- 两位数字从 01 起，**连续不跳号**
- 例：`SC01`

**镜头 ID**（`shots.json` 的 `id`）：

```
SC<NN>-SH<NN>
```

- `SC` = Scene（场次），`SH` = Shot（镜头），均两位数字从 01 起
- 例：`SC01-SH03`
- **镜头顺序即播放顺序**，不做其他编号
- 一个场次内的镜头必须连续编号，不允许跳号
- 镜头 id 的场次前缀必须与 `scenes.json` 里的场次 id 对得上

### 2.3 资产文件命名

| 类型 | 模板 | 例 |
|---|---|---|
| 角色参考图 | `<role>_<state>_<tag>.png` | `cellist_wet_full.png` |
| 道具参考图 | `prop_<name>_<tag>.png` | `prop_cello_closeup.png` |
| 场景参考图 | `loc_<name>_<tag>.png` | `loc_streetcorner_night.png` |
| 镜头关键帧 | `<shot-id>.png` | `SC01-SH03.png` |
| 视频片段 | `<shot-id>_v<NN>.mp4` | `SC01-SH03_v02.mp4` |
| 提示词 | `<shot-id>.prompt.txt` | `SC01-SH03.prompt.txt` |
| 配音 | `<shot-id>_L<NN>_<role>.wav` | `SC01-SH03_L01_cellist.wav` |
| 验收报告 | `<shot-id>.report.json` | `SC01-SH03.report.json` |
| 创作文档 | `creative/<name>.md` | `creative/brief.md` |

**规则**：
- 版本号 `v<NN>` 从 `01` 起，两位数，**只增不改**。
- 重新生成一个镜头 → 新版本号，**旧文件保留**（废片也要留，用于对比）
- 文件名只允许 `[A-Za-z0-9_-]` 和中文，**禁止空格**（Windows 兼容 + 跨平台安全）
- 同一镜头不可能有两条"当前有效"版本；当前有效版本由 `shots.json` 的 `current_version` 字段指定

### 2.4 角色 ID `<role>`

小写英文，无空格：`cellist`、`boy`、`narrator`。角色 ID 在全作品内唯一。

**ID 在 outline 阶段定稿**（`scenes.json` 的 `characters` 数组里首次出现），characters 阶段沿用**不改名**——一条链下来不用反复翻译。`scenes.json`、`characters.json`、`shots.json` 三处必须完全一致。

道具 ID 用 `prop_<name>` 前缀，与角色 ID 区分。

### 2.5 状态标识 `<state>`

角色在不同状态下的视觉差异必须用 state 区分：

```
dry / wet / bloodied / broken / happy / sad / asleep
```

**关键规则（实测结论）**：**同一镜头禁止混合互斥 state 的同一角色参考图**。
例如不能同时喂"湿身"和"干身"参考图——模型会取平均或偏向其中一个，导致状态错误。
需要多状态时用 `<Picture N>` 声明角色 + 消歧句，或拆成多次生成。

**唯一登记册**。任何资产文件必须在此登记，未登记 = 不存在。

```json
{
  "version": "1.0",
  "assets": [
    {
      "id": "cellist_wet_full",
      "type": "reference_image",
      "path": "refs/cellist_wet_full.png",
      "role": "cellist",
      "state": "wet",
      "tags": ["full", "front"],
      "width": 1792,
      "height": 2400,
      "bytes": 5767159,
      "sha256": "…",
      "created_at": "2026-11-01T13:21:00Z",
      "created_by": "human|agent|tool",
      "source": "qwen-image-3.0-pro",
      "notes": "湿身状态基准参考，全片统一使用此图"
    },
    {
      "id": "SC01-SH03",
      "type": "video",
      "path": "videos/SC01-SH03_v01.mp4",
      "shot_id": "SC01-SH03",
      "version": 1,
      "width": 1344,
      "height": 768,
      "duration_sec": 5.167,
      "bytes": 995608,
      "sha256": "…",
      "created_at": "2026-11-01T13:23:49Z",
      "created_by": "agent",
      "source": "MiniMax-H3",
      "task_id": "458578621747790",
      "cost_usd": 0.40,
      "prompt_sha256": "…",
      "references": ["cellist_wet_full", "cellist_dry_full"],
      "verify": { "status": "pass", "report": "verify/SC01-SH03.report.json" }
    }
  ]
}
```

### 字段规则

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✅ | 全局唯一，等于文件名主干 |
| `type` | ✅ | `reference_image` / `keyframe` / `video` / `audio` / `prompt` / `report` / `doc` |
| `path` | ✅ | 相对作品目录的 POSIX 风格路径 |
| `sha256` | ✅ | 内容哈希，用于查重与"是否被修改"判定 |
| `created_at` | ✅ | ISO 8601 UTC |
| `source` | ✅ | 生成该资产的模型/工具名 |
| `references` | 视频类必填 | 该资产用到的上游资产 id，构成依赖图 |
| `task_id` | 视频类必填 | provider 任务 id，唯一标识一次生成 |
| `cost_usd` | 视频类必填 | 该次生成的估算成本 |

**规则**：
- `references` 构成**依赖图**，支持"改了 A 要重生成哪些下游"
- `sha256` 是查重依据：同 hash = 同内容，不重复生成
- `assets.json` 只增不删（废片标 `"status": "deprecated"`，不删记录）

```json
{

  "budget": {
    "limit_usd": 30.0,
    "spent_usd": 2.0,
    "billing_mode": "M Plan weekly window",
    "model": "MiniMax-H3",
    "resolution": "768P",
    "cost_per_shot_usd": 0.40
  },
  "notes": "自 2026-11-01 起，H3 实测约 2 分钟/条"
}
```

### 阶段枚举（固定顺序）

```
conceive → outline → characters → script → storyboard
         → generate → verify → assemble → deliver
```

**规则**：
- 阶段只能顺序前进，**允许回退**（分镜返工要能只重做第 7 个镜头）
- **正向推进时 CLI 会校验前置条件**（见 §9），不满足则拒绝推进并列出缺口；回退不校验
- 确需跳过时用 `drama advance --force`，并在 `notes` 记录原因
- `shots_done` / `shots_failed` 由 CLI 自动维护，Agent 不手改

## 5. 生成台账 `ledger.json`

**幂等的核心**。记录每一次生成任务的完整生命周期。

```json
{
  "version": "1.0",
  "entries": [
    {
      "task_id": "458578621747790",
      "shot_id": "SC01-SH01",
      "model": "MiniMax-H3",
      "resolution": "768P",
      "duration": 5,
      "ratio": "16:9",
      "references": ["cellist_wet_full", "cellist_dry_full"],
      "prompt_sha256": "…",
      "submitted_at": "2026-11-01T13:22:03Z",
      "last_query_at": "2026-11-01T13:23:49Z",
      "status": "succeeded",
      "node_id": "458578677183769",
      "output_path": "videos/SC01-SH01_v01.mp4",
      "cost_usd": 0.40,
      "poller_task_id": null
    }
  ],
  "totals": { "cost_usd": 2.0, "tasks": 5, "succeeded": 5, "failed": 0 }
}
```

### 幂等规则（不可违反）

1. **提交前**先在 ledger 写入 `status: "submitting"` + 请求指纹
2. 提交后**立刻**回写 `task_id`，状态改 `submitted`
3. **超时/网络失败**：先查 ledger 和 provider 任务列表，**绝不直接重发**
4. H3 V2 API **没有幂等键**，重复提交 = 重复扣费
5. 每个 `task_id` 只允许一个 poller

**规则**：CLI 负责 ledger 的读写与唯一性校验；Agent 只调用 `drama task add` / `drama task record`。

## 6. 场次表 `scenes.json`

**outline 与 script 两个阶段的产物。** outline 填场次骨架，script 填 `beats`。

```json
{
  "version": "1.0",
  "scenes": [
    {
      "id": "SC01",
      "index": 1,
      "act": 1,
      "title": "拾音斋清晨",
      "function": "建置",
      "duration": 20,
      "summary": "掌柜连喊三声典号，阿铃笔不停、头不抬地应了一声。",
      "turn": "观众知道她的真名并非本名，而她装作不知道。",
      "characters": ["aling", "shopkeeper"],
      "beats": [
        {
          "action": "掌柜把笔搁上笔架，抬眼看她——第一声喊得很轻，像在点一个号",
          "speaker": "shopkeeper",
          "text": "十九。",
          "mode": "dialogue",
          "delivery": "第一声，轻，像点号，尾音不扬，落下即止"
        },
        {
          "action": "她没应；她的笔没停，头没抬，左手小指压住纸角",
          "speaker": null,
          "text": null,
          "mode": null
        },
        {
          "action": "视线掠过柜台另一本摊开的账册",
          "speaker": null,
          "text": null,
          "mode": null
        }
      ]
    }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✅ | `SC01`，两位数字从 01 起，**连续不跳号** |
| `index` | ✅ | 与 id 后缀一致 |
| `act` | ✅ | 1 / 2 / 3 |
| `function` | ✅ | 建置 / 升级 / 揭示 / 转折 / 收束 |
| `duration` | ✅ | 预估秒数；全片之和 ≈ 总时长（±15%） |
| `summary` | ✅ | 一句话说明这一场发生了什么 |
| `turn` | | 这一场结束时什么变了 |
| `characters` | ✅ | 角色 ID 数组，**ID 在 outline 阶段定好，characters 阶段沿用不改名** |
| `beats` | | script 阶段填；outline 阶段留空数组 |
| `beats[].mode` | | `dialogue`（画内音，有口型）/ `voiceover`（画外音，无口型）/ `null`（无台词） |
| `beats[].delivery` | ✅（`mode=dialogue` 时） | **本句的语气阶梯**：情绪 + 语速 + 气口。同一角色不同台词的 `delivery` 必须不同（R18③） |
| `beats[].action` | ✅ | **可被镜头拍到的动作**。禁止否定式表演词（`始终没抬眼` / `一动不动`）——「没有动作」在生成端等于木头人。克制要写成**被压住的动作**（R18①） |

## 7. 角色表 `characters.json`

**characters 阶段的产物。**

```json
{
  "version": "1.0",
  "characters": [
    {
      "id": "aling",
      "name": "阿铃",
      "role": "主角",
      "age": "17-18",
      "appearance": "齐耳短发，左侧铜夹；瘦小；右手食指有墨渍",
      "behavior": "记账时左手小指压住纸角；被叫典号时手不停、头不抬",
      "voice": "短句，少用主语，回答只用一个字；从不辩解",
      "states": ["dry"],
      "props": ["prop_benmingqi"],
      "reference_assets": ["aling_dry_full", "aling_face"],
      "voice_desc": "a calm, low-pitched young female voice, slightly husky, steady tempo, clear diction",
      "delivery_default": "flat and unhurried, answers clipped to single words, never defensive"
    }
  ],
  "props": [
    {
      "id": "prop_benmingqi",
      "name": "本名契",
      "appearance": "泛黄宣纸，折痕三道，右下角一枚朱砂印",
      "owner": "aling",
      "reference_assets": ["prop_benmingqi"]
    }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✅ | 小写英文无空格，全作品唯一；与 `scenes.json` 里出现的完全一致 |
| `appearance` | ✅ | 发型 / 脸型 / 体型 / 标志物 |
| `behavior` | ✅ | **一个可被镜头拍到的动作**，不是性格形容词 |
| `age` | | 外显年龄。**必须与参考图一致**，否则模型跟着参考图走 |
| `states` | ✅ | 视觉状态数组，**必须穷举本片会出现的全部状态** |
| `reference_assets` | ✅ | `assets.json` 里的资产 id；登记时的 `--role` / `--state` 必须与本表一致 |
| `voice_desc` | | **音色**描述词（声线质感、性别、音域），**逐字复制**到每条需要此角色说话的提示词里，不许每条现写。**只放音色，不放语气** |
| `delivery_default` | | **默认语气**（该角色的说话习惯）。可被每句台词的 `delivery` 覆盖 |

> **音色与语气必须分开（R9 修订，2026-11-12）**
> 原写法要求「逐字复用同一段音色描述词」，Agent 就把**语气词一起复用了**——
> 掌柜全片 15 句、阿铃 6 句全部同一口气，听起来像有声书。
> 现在：`voice_desc` 只管音色（逐字复用）；`delivery_default` 是默认语气；
> 每句台词另写 `delivery`（本句情绪、语速、气口）。
> 提示词里**音色那句照抄 `voice_desc`，语气那句另起一行**。

### 7.1 台词拍 `delivery` 字段

`scenes.json` 的 beat 若含台词，必须带 `delivery`：

```json
{
  "id": "SC02-b3",
  "type": "dialogue",
  "character": "shopkeeper",
  "action": "掌柜右手食指按住笔架，声音压低，像在报一个只有他自己听得见的数",
  "dialogue": "十九。",
  "delivery": "第一声，轻，像点号，尾音不扬，落下即止"
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `delivery` | ✅（有台词时） | **本句的语气阶梯**：情绪 + 语速 + 气口。同一角色不同台词的 `delivery` 必须不同，否则听起来是机器复读 |
| `action` | ✅ | **可被镜头拍到的动作**。禁止否定式表演词（`始终没抬眼` / `一动不动`）——「没有动作」在生成端等于木头人。克制要写成**被压住的动作** |

## 8. 分镜表 `shots.json`

```json
{
  "version": "1.0",
  "shots": [
    {
      "id": "SC01-SH01",
      "scene": "SC01",
      "index": 1,
      "title": "雨中拉琴",
      "duration": 5,
      "ratio": "16:9",
      "resolution": "768P",
      "model": "MiniMax-H3",
      "description": "大提琴手独自坐在积水边的石墩上拉琴",
      "camera": "medium, slow Push In",
      "lighting": "day_interior",
      "characters": [{ "role": "cellist", "state": "wet" }],
      "references": ["cellist_wet_full"],
      "dialogue": [],
      "audio": { "voiceover": false, "soundscape": "雨声、弓弦、雨滴", "music": "大提琴独奏" },
      "current_version": 1,
      "status": "pending",
      "notes": ""
    }
  ]
}
```

**规则**：
- `shots` 数组顺序 = 播放顺序
- `references` 引用的 id 必须在 `assets.json` 中存在
- `current_version` 指向 `videos/` 中的当前有效版本
- `status`: `pending` / `submitted` / `succeeded` / `failed` / `verified` / `deprecated`
- **`lighting`**（2026-11-14 新增）：该镜头的**光参数 preset 键**。风格锚在 H3-Image 端能继承光比，
  在 **H3 视频端会衰减一档**（实测线条更硬、饱和更低、锚里的浮尘消失），所以视频端必须在提示词里
  **显式重建光参数**。preset 定义见 `workspaces/<work-id>/prompts/lighting.py`，
  提示词里的 `Lighting:` 行必须与该 preset 逐字一致（由 `check_prompts_v2.py` 对账）

## 9. 验收报告 `verify/<shot-id>.report.json`

```json
{
  "shot_id": "SC01-SH01",
  "version": 1,
  "tech": {
    "duration_sec": 5.167,
    "width": 1344,
    "height": 768,
    "ratio_check": "16:9",
    "has_audio": true,
    "mean_volume": "-18.6dB",
    "max_volume": "-0.7dB",
    "pass": true
  },
  "semantic": {
    "note": "机器判定仅作参考，不作判废依据",
    "dialogue_match": true,
    "lipsync": "unclear",
    "camera": "slow push-in",
    "character_match": true
  },
  "human": {
    "verdict": "pass",
    "reviewer": "QWQ",
    "checked_frames": ["keyframe_first", "keyframe_last"],
    "issues": ["口型不明显"]
  },
  "verdict": "pass",
  "verified_at": "2026-11-01T13:40:00Z"
}
```

**规则**：
- `tech` 由 `drama verify` 自动生成
- `semantic` 由视频理解生成，**仅作参考**
- `human` 段落**必须人工填写**才能把 `verdict` 定为 `pass`
- **机器判定与人工判定冲突时以人工为准**（实测中机器对相机运动判定不自洽）

## 11. 阶段路由与前置条件

### 11.1 路由由 CLI 裁决

```bash
python tools/drama/drama.py next --work <work-id>
```

返回：

```json
{
  "stage": "generate",
  "skill": "drama-generate",
  "skill_path": ".agents/skills/drama-generate/SKILL.md",
  "skill_status": "split",
  "action": "写 H3 提示词并提交生成",
  "hint": "task add → 提交 → task record → poll",
  "rules": [{ "id": "R2", "title": "…", "text": "…" }],
  "references": [{ "path": ".drama/references/h3-官方提示词规范.md", "why": "…" }],
  "constitution": "…"
}
```

**规则**：
- `skill` 指向该阶段应加载的技能。阶段已拆分 → `drama-<stage>`；未拆分 → 过渡技能 `minimax-drama`（`skill_status: "pending_split"`）
- `rules` 由 CLI 从 `.drama/rules.md` 按阶段筛选后注入，**Agent 不凭记忆执行**
- `references` 是渐进披露清单：**用到才读**，不要一次性全读进上下文
- `constitution` 是生效的创作宪法（作品级覆盖项目级）

### 11.2 前置条件

| 推进到 | 必须已存在 |
|---|---|
| `outline` | `creative/brief.md`（非空） |
| `characters` | `scenes.json` 中至少一个场次 |
| `script` | `assets.json` 中至少一个带 `role` 的角色参考图 |
| `storyboard` | 每个场次都有 `beats`（动作或台词） |
| `generate` | 每个镜头都有 `duration` 与 `camera` |
| `verify` | 每个镜头都有已登记的视频资产 |
| `assemble` | 每个镜头的 `status` 已是 `verified` |
| `deliver` | 已登记成片（视频资产路径含 `final`） |

不满足时 `drama advance` 返回退出码 **3** 并列出具体缺口。

## 12. 记忆层 `.drama/`

| 文件 | 内容 | 覆盖规则 |
|---|---|---|
| `rules.md` | R1–R12 硬规则，**唯一真源** | 不覆盖 |
| `constitution.md` | 创作宪法（叙事/题材/角色/台词/视觉/声音） | `workspaces/<id>/constitution.md` 覆盖它 |
| `templates/<name>.md` | 模板骨架 | `.drama/presets/<preset>/templates/<name>.md` 作为兜底层 |
| `references/*.md` | 参考资料 | 不覆盖 |

**规则**：
- `rules.md` 与 `constitution.md` 里**不放方法**，只放约束；方法在对应技能的 SKILL.md 里
- 改记忆层后无需改任何 SKILL.md，CLI 下次注入即生效
- 铁律条目用 `## R<数字> <标题>` 开头，CLI 按此解析
